# 사전 설계 동료 (가칭)

> 2026 AI 우왕톤 · TEAM 11 · 주제 "AI는 동료가 될 수 있을까?"

## 한 줄 소개
비싼 코딩 AI에게 앱을 맡기기 전에, **싼 AI가 먼저** 해석이 갈리는 지점과 이 프로젝트에 필요한 유지보수·보안 규칙을 **카드로 정리**해 주고, 사람은 **고르기만** 하면 코딩 AI용 사양서가 나온다.

## 문제
- 대상 사용자: 바이브코딩으로 앱을 만드는 청년 (학생, 예비 창업자, 비전공자)
- 문제: 모호한 요청 → AI가 임의로 채움 → 다시 요청하며 **토큰 낭비**, 구조 없는 **스파게티 코드**, 키 노출·권한 미검사 같은 **보안 구멍**
- 문제의 근거: _수집 중_ (docs/SOURCES.md)

## 해결
| | |
|---|---|
| AI가 하는 일 | 요청에서 해석이 갈리는 지점을 찾아 선택 카드로 만들고(추천안 포함), 결정된 내용으로 작업 계획을 세운다 |
| 규칙 기반으로 하는 일 | 고른 카드로 프로젝트 성격을 계산해 유지보수·보안 규칙을 추천한다. 같은 선택이면 항상 같은 추천 |
| 사후 점검 | 코딩 AI가 만든 코드를 붙여넣으면, 패턴으로 확정 가능한 위반(키 하드코딩, 빈 catch, 긴 파일)은 규칙 검사로, 나머지는 AI가 판단해 짚어준다 |
| 사람이 결정하는 일 | 카드와 규칙을 고르고, 점검 결과 중 고칠 항목을 고른다 (고른 항목만 수정 요청문으로 만들어짐) |
| 기존 방식과의 차이 | 설계를 비싼 코딩 에이전트 안에서 하지 않고 **무료 경량 모델**이 앞단에서 처리. 개발자가 아니어도 카드만 고르면 됨. 프로젝트 성격에 맞는 규칙을 자동 선택 |

AI 호출이 실패하거나 무료 한도를 넘으면 **기본 카드·기본 계획으로 계속 동작**하고, 화면에 "AI 미사용 · 기본값"과 사유를 표시한다.

## 구조
```
packages/core   순수 로직 (UI·네트워크 없음): 카드 파싱, 프로필 계산, 규칙 프리셋, 사양서 생성, LLM 클라이언트
apps/web        Vite + React 화면, server/ 요청 핸들러, functions/ 배포용 엔드포인트
scripts/        Vercel Build Output 생성 (esbuild로 함수 번들)
```
- LLM: OpenAI 호환 인터페이스 → Gemini Flash-Lite(무료) 우선, 실패 시 Flash. `LLM_BASE_URL`·`LLM_MODELS`로 제공자 교체 가능
- 서버는 입력 검증·요청 횟수 제한 후 core를 호출만 한다

## 실행 방법
```bash
cp .env.example .env      # GEMINI_API_KEY 입력 (Google AI Studio 무료 키)
npm install
npm run dev               # http://localhost:5173
npm run check             # 타입 검사 + 테스트
```
