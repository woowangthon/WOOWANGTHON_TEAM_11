# 사전 설계 동료 (가칭)

> 2026 AI 우왕톤 · TEAM 11 · 주제 "AI는 동료가 될 수 있을까?"

## 한 줄 소개
비싼 코딩 AI에게 앱을 맡기기 전에, **싼 AI가 먼저** 해석이 갈리는 지점과 이 프로젝트에 필요한 유지보수·보안 규칙을 **카드로 정리**해 주고, 사람은 **고르기만** 하면 코딩 AI용 사양서가 나온다. 코딩 AI가 코드를 만든 뒤에는 규칙을 지켰는지 **점검**해서 고칠 것만 골라 다시 요청한다.

## 문제
- 대상 사용자: 바이브코딩으로 앱을 만드는 청년 (학생, 예비 창업자, 비전공자)
- 문제: 모호한 요청 → AI가 임의로 채움 → 다시 묻고 고치는 **왕복으로 토큰 낭비**, 구조 없는 **스파게티 코드**, 키 노출·권한 미검사 같은 **보안 구멍**
- 근거: AI 생성 코드의 45%가 OWASP Top 10 보안 테스트 실패(Veracode 2025), 배포된 바이브코딩 앱 5,600개에서 노출된 비밀키 400+(Escape.tech) 등 — 출처는 [docs/SOURCES.md](docs/SOURCES.md)

## 흐름 (6단계)
| 단계 | 하는 일 | 방식 |
|---|---|---|
| 1 요청 | 만들고 싶은 앱을 평소 말투로 입력 | — |
| 2 갈림길 | 먼저 **프로젝트 규모 판정**(목적별 혼자 가능 / 팀 필요 / 기업급, 이유·위험·축소 범위). 해석이 갈리는 지점을 카드로(비즈니스 규칙 먼저, 보기별 난이도), 추천안 미리 선택. **곧 필요해질 기능**을 미리 제안하면 지금/나중에/필요 없음만 고름 | **AI** + 규칙 바닥(암호화폐·금융·의료는 기업급) |
| 3 규칙 | 고른 내용에 맞는 유지보수 규칙 9종·보안 규칙 10종 중 필요한 것을 추천 | 규칙 기반 (같은 선택 → 같은 추천) |
| 4 사양서 | 코딩 AI용 영어 사양서(CLAUDE.md/AGENTS.md) + 한국어 확인본, 작업별 **난이도·왜 어려운지·다룰 문제**, **추천 기술 스택**, **추정 예산(무료로 어디까지)**, **이 앱 맞춤 보안 확인**, '나중에' 기능은 구조만 열어두라는 지시 | **AI** (계획·예산·번역) + 규칙 기반(기본 보안 점검 안내문) |
| 5 보드 | 작업을 할 일→진행 중→사람 확인→완료로 관리. 보안 확인을 체크해야 완료 가능, 마크다운 내보내기 | 규칙 기반 |
| 6 점검 | 코딩 AI가 만든 코드를 붙여넣으면 규칙 위반을 짚고, 고칠 것만 골라 수정 요청문 생성 | 규칙 검사 + **AI** 판단 |

- **사람이 결정하는 일**: 카드 고르기, 제안 기능 지금/나중에/필요 없음, 규칙 켜고 끄기, 보안 항목 직접 확인 후 완료 처리, 고칠 항목 고르기
- 오른쪽 **실시간 요약**: 정한 것, 적용 중인 유지보수·보안 규칙, 추천 스킬(Stripe·Supabase·Trail of Bits·Vercel 같은 도메인 스킬 우선, 어느 작업에 쓰는지)이 항상 보임
- AI 호출이 실패하거나 무료 한도를 넘으면 **기본값으로 계속 동작**하고 화면에 "AI 미사용 · 기본값"과 사유를 표시

## 기존 방식과의 차이
- Kiro spec·spec-kit·plan mode는 **비싼 코딩 에이전트 안에서** 설계하고 개발자용 → 여기서는 **무료 경량 모델이 앞단**에서 처리
- 개발자가 아니어도 카드만 고르면 됨
- 프로젝트 성격에 맞는 유지보수·보안 규칙을 **자동 선택**하고, 만든 뒤 **점검**까지 이어짐

## 검증
- 사양서 유무 비교 (요청 3건): 사양서가 있으면 환경변수 사용·입력 검증·파일 분리가 **3건 모두** 지켜짐(없으면 0건). 첫 시도 출력 토큰은 줄지 않음 → [docs/experiment/INTERPRETATION.md](docs/experiment/INTERPRETATION.md)
- 왕복 횟수 실험(위반 0까지 몇 번 다시 요청하나, 코딩은 맥락 없는 Claude 서브에이전트): 사양서가 있으면 두 요청 모두 **첫 답에서 위반 0**, 없으면 수정 요청 2회·1회 → [docs/experiment/rounds-agent/INTERPRETATION.md](docs/experiment/rounds-agent/INTERPRETATION.md)
- 규모 판정 점검(기대 규모를 정한 요청 9개): 최종 9/9 일치 → [docs/experiment/difficulty/README.md](docs/experiment/difficulty/README.md)
- 요청 수가 적어 통계가 아닌 경향 확인 수준. AI 적용·미검증 범위는 [docs/SCOPE.md](docs/SCOPE.md)

## AI 제공자와 API 키
- 기본: Google Gemini Flash-Lite → Flash (무료, 서버 키)
- 선택: 화면의 **AI 설정**에서 내 Claude(Anthropic 공식 SDK) / GPT / Gemini 키 사용
- 키 보안: 브라우저 메모리에만 보관(선택 시 탭 세션까지), 헤더로 전송, 서버는 허용 목록의 **고정 주소로만** 전달하고 저장·로그하지 않음, 오류엔 상태 코드만, 배포 시 CSP `connect-src 'self'` — 상세는 [docs/SCOPE.md](docs/SCOPE.md)

## 구조
```
packages/core   순수 로직 (UI 없음): 카드 검증, 프로필 계산, 규칙·스킬 프리셋, 작업 계획, 사양서(영/한),
                사후 점검, 번역, LLM 클라이언트(OpenAI 호환 + Anthropic SDK), BYOK 검증
apps/web        Vite + React 화면, server/ 요청 핸들러(입력 검증·요청 횟수 제한), functions/ 배포용 엔드포인트
scripts/        Vercel Build Output 생성(esbuild로 edge 함수 번들, 보안 헤더), 비교 실험 스크립트
```

## 실행 방법
```bash
cp .env.example .env      # GEMINI_API_KEY 입력 (Google AI Studio 무료 키)
npm install
npm run dev               # http://localhost:5173
npm run check             # 타입 검사 + 테스트
```
