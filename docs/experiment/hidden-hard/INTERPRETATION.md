# 서비스가 제 역할을 하는가 (11/14)

이 서비스가 하겠다는 일은 세 가지다: 요구사항을 미리 더해 주고, 난이도를 가늠하게 하고, 너무 어려운 것(겉보기엔 쉬운 것 포함)을 시작 전에 알려 준다. 세 가지를 실제 호출로 쟀다.

아래 수치는 AI 응답이 온 실행만 센 것이다. 88회 중 9회는 무료 모델이 응답하지 못해 '기본값'이 나갔고 판정에서 뺐다 (같은 날 실험을 몰아 돌려 무료 한도에 걸린 영향이 큼).

## 1. 요구사항을 미리 더해 주는가
한 줄 요청 22개에서 요청당 평균 **비즈니스 규칙 카드 2.3~2.6개, 기술 선택 카드 1.8~1.9개, 곧 필요해질 기능 제안 3.6~3.8개**. 요청에 없던 결정 사항을 매번 8개쯤 끌어낸다. 개수만 센 것이고 질문의 쓸모는 사람이 평가하지 않았다.

## 2. 쉬워 보이지만 모델을 직접 학습시켜야 하는 AI 서비스

| | '혼자는 어려움' 이상으로 판정 | 원본 |
|---|---|---|
| 규칙 넣기 전 (요청 8개 × 2회) | 10/15 | before-rule/ |
| 학습 바닥 규칙을 넣은 뒤, 같은 요청 | 11/14 | README.md |
| 규칙을 만들 때 보지 않은 새 요청 5개 × 2회 | 7/8 | held-out/ |

- 규칙 넣기 전에는 **"내 그림체를 학습하는 AI", "사투리를 알아듣는 음성 비서"를 두 번 다 "API 연동이면 된다"며 '혼자 가능'으로 봤다.** 이 서비스가 잡아야 할 바로 그 경우를 놓친 것이다
- 그래서 규칙을 추가했다 (`packages/core/src/feasibility.ts`): 목소리·그림체 학습, 사투리·수어 인식, 파인튜닝처럼 모델을 직접 학습시켜야 하는 요청은 최소 '혼자는 어려움'으로 올리고, 화면에 "데이터 수집, 학습용 GPU 비용, 정확도 검증이 따로 필요하다. 먼저 기존 AI API로 되는지 확인하라"고 이유를 보여 준다
- 같은 요청의 수치가 오른 것은 규칙을 그 요청을 보고 만들었으니 당연하다. 의미 있는 것은 새 요청 쪽 7/8이다. 놓친 1회는 "고양이 울음소리로 기분 맞히기"(규칙에 걸리는 단어가 없고 AI도 '혼자 가능'으로 봄)
- **여전히 흔들리는 것**: "얼굴로 출석 체크"는 규칙 전에는 두 번 다 '혼자는 어려움', 규칙 후 실행에서는 두 번 다 '혼자 가능'이 나왔다(규칙과 무관한 AI의 흔들림). "주가 예측 AI"도 한 번 '혼자 가능'이 나왔다. 규칙이 없는 영역은 무료 모델의 판단에 달려 있고, 그 판단은 회차마다 달라진다

## 3. 기존 API로 되는 AI 서비스를 괜히 겁주지 않는가
자소서 첨삭, PDF 요약, OCR, 회의 받아쓰기, 여행 일정, "영어 단어 학습 앱"(사람이 학습하는 앱) 등: **26/26회 '혼자 가능'**. 새 규칙이 이쪽을 잘못 올린 경우는 없었다.
