# 구현 범위

대회 규칙: 직접 구현한 부분과 외부 기술을 구분하고, AI 미적용·미검증 상태와 테스트 계정·샘플·모킹 범위를 밝힌다.

## 직접 구현
- 6단계 웹 화면: 요청 → 갈림길 → 규칙 → 사양서(사양서 / 작업·난이도 / 예산 / 보안 확인 탭) → 보드 → 점검
- AI 응답 검증·정규화 (`packages/core/src/cards.ts`, `tasks.ts`, `feasibility.ts`, `features.ts`, `review.ts`): 모델 출력의 키·값을 고정된 어휘로 검사하고, 잘못된 항목은 그 항목만 버림 (카드 하나, 점검 항목 하나, 판정 하나가 전체를 버리지 않게)
- 프로필 계산과 규칙 추천 (`profile.ts`, `recommend.ts`, `presets/`): 규칙 기반, 결정적. 유지보수 규칙 9종·보안 규칙 10종 문구
- 프로젝트 규모 판정의 규칙 바닥 (`feasibility.ts`): 암호화폐·금융·의료는 기업급, 실시간 대규모·결제·마켓·판매 계획은 최소 팀. 목적(개인/공개/판매) 명시 감지
- 작업 난이도 보정 (`calibrateDifficulty`): 성능·결제·실시간 같은 주제는 '상'으로 올림. 스택 겹침 경고 (`stackWarnings`)
- 사양서 조립 (`spec.ts`, 영/한), 번역 대상 추출과 되돌리기 (`translatableTexts` / `withTexts`), 남은 한글 줄 재번역·집계 (`translate.ts`)
- 스킬 카탈로그 (`skills.ts`): 도메인·범용 구분, 프로필 기반 추천, AI 선택과 규칙 추천 합치기 (`mergeSkills`)
- 작업 보드 (`board.ts`): 보안 확인을 체크하지 않으면 완료로 못 옮김, 브라우저에만 저장
- OpenAI 호환 LLM 클라이언트와 모델 폴백 (`llm.ts`), 사용자 키 제공자 허용 목록 (`providers.ts`)
- 요청 핸들러(입력 검증·요청 횟수 제한, `apps/web/server/handlers.ts`), 배포 빌드 스크립트 (`scripts/build-vercel.mjs`)
- 비교 실험 스크립트 (`scripts/experiment*.ts`, `scripts/eval-difficulty.ts`)

## 외부 기술 (API·라이브러리·모델)
- Google Gemini API (OpenAI 호환 엔드포인트), 모델 `gemini-flash-lite-latest` → `gemini-flash-latest`
- 사용자 키 사용 시(선택): Anthropic Claude (공식 SDK `@anthropic-ai/sdk`, 기본 `claude-opus-5-5`, 거절 시 서버측 fallback), OpenAI Chat Completions
- React, Vite, esbuild, TypeScript, lucide-react(아이콘), Pretendard(글꼴)
- Vercel (배포), GitHub Actions (CI)
- 추천 스킬은 외부 저장소(anthropics, obra/superpowers, Stripe, Supabase, Trail of Bits, Vercel, difficcd/skills-workshop)의 것이고 이 서비스는 이름·링크·설치 방법만 안내함. 각 저장소·스킬 폴더는 추가할 때 GitHub에서 존재를 확인함

## AI 적용 범위
| 단계 | 방식 |
|---|---|
| 프로젝트 규모 판정 | AI (목적·규모·이유·위험·축소 범위) + 규칙 바닥. 규칙이 올리면 화면에 이유 표시. AI 실패 시 규칙 판정만 '규칙 판정 (AI 판단 없음)'으로 표시, 일반 앱은 판정 없음 |
| 갈림길 카드 생성 | AI (비즈니스 규칙 먼저, 보기별 난이도). 실패 시 기본 카드 6장, '기본값'으로 표시 |
| 곧 필요해질 기능 제안 | AI. 실패 시 제안 없음 (고정 목록을 맞춤 조언처럼 보이게 하지 않음) |
| 규칙 추천 | **AI 미적용** — 규칙 기반 (설명 가능성을 위해 의도적으로) |
| 작업 계획·추천 스택·예산·맞춤 보안 확인 | AI. 실패 시 프로필 기반 기본 계획, 맞춤 보안 확인·스킬은 지어내지 않고 비움 |
| 기본 보안 점검 7종 | **AI 미적용** — 고정 안내문, 화면에 '기본 점검 (고정 안내문)'으로 표시 |
| 스킬 추천 | AI가 카탈로그 안에서 고름 + 프로필이 분명히 요구하는 도메인 스킬은 규칙으로 추가('규칙 추가' 표시). AI 실패 시 규칙 기반 목록, '기본 · 규칙 기반'으로 표시 |
| 사양서 조립 | **AI 미적용** — 템플릿 조립 |
| 영어 사양서 번역 | AI (한글 남은 줄은 한 번 더). 그래도 남거나 실패하면 'N줄 미번역'과 다시 시도 버튼 |
| 보드 | **AI 미적용** — 보안 확인 완료 여부는 사람이 체크 |
| 사후 점검 | 규칙 검사(정규식: 키 하드코딩·빈 catch 확정, 긴 파일은 확인 필요) + AI 판단(나머지 규칙). 규칙 검사로 확정된 위반은 AI 의견으로 뒤집지 않음. AI 실패 시 규칙 검사 결과만 표시 |

## 검증한 것 (실측, 원본은 `docs/experiment/`)
- 사양서 유무 비교 1차: 사양서가 있으면 환경변수·입력 검증·파일 분리 3/3, 없으면 0/3. 첫 시도 출력 토큰은 줄지 않음
- 왕복 횟수 실험(#6, 11/14에 요청 5건으로 확대): 맥락 없는 Claude 서브에이전트가 코딩, 서비스와 같은 점검. 사양서가 있으면 5건 모두 첫 답에서 위반 0, 없으면 4건에서 수정 요청 1~3회(2·1·1·3·0회). 단순한 앱 1건은 차이 없음. 조건당 1회라 경향 확인 수준
- 규모 판정 반복 점검(11/14): 요청 20개 × 3회 = 60회 중 최종 54회(90%) 일치, AI 단독 48회(80%). 3회 모두 같은 판정이 나온 요청은 15/20. 틀린 6회 = 무료 모델 응답 실패 3 + 오판 3(실시간 단체 채팅 2, 음식 배달 앱 1). 실시간 채팅은 이후 규칙에 추가
- 숨은 난이도 점검(11/14): 모델을 직접 학습시켜야 하는 AI 서비스를 규칙 전 10/15회만 '혼자는 어려움' 이상으로 판정("내 그림체 학습", "사투리 음성 비서"를 놓침) → 학습 바닥 규칙 추가 → 규칙을 만들 때 보지 않은 새 요청에서 7/8회. 기존 API로 되는 AI 서비스는 26/26회 '혼자 가능'. 규칙이 없는 영역(얼굴 인식, 주가 예측 등)은 회차마다 판정이 흔들림
- 11/4 규모 판정 점검(요청 10개 × 1회, 10/10)은 위 반복 점검의 앞 10개와 같은 요청

## 미검증
- 비전공자가 도움 없이 끝까지 쓸 수 있는지 (사용자 테스트 #14는 일정상 하지 않기로 11/14 결정)
- 예산은 AI 추정치이며 실제 청구액이 아님 (화면에 '추정' 표시)
- 사양서 토큰 수는 토크나이저 없이 문자 수로 추정한 값 (화면에 '추정' 표시)
- 실험은 요청 수가 적어 통계적 결론이 아님. 점검 모델(Flash-Lite)이 회차마다 판정이 흔들리는 것을 관찰함

## 샘플 · 모킹 · 테스트 계정
- 기본 카드·기본 계획은 AI 실패 시에만 쓰이며 화면에 'AI 미사용 · 기본값'과 사유를 표시
- 점검 단계의 '샘플 코드로 체험'은 일부러 문제를 넣은 예시 코드이며 화면에 '샘플 코드' 표시. 점검 자체는 매번 실제 호출
- 예시 요청 버튼 3개는 입력 편의용 샘플 문장 (결과는 매번 실제 AI 호출)
- 로그인 없음, 테스트 계정 불필요. 보드 상태는 사용자 브라우저(localStorage)에만 저장

## 사용자 API 키(BYOK) 보안
- 키는 브라우저 메모리에만 둔다. '이 탭에서 기억'을 켠 경우만 sessionStorage(탭 닫으면 삭제). localStorage에는 저장하지 않음
- 요청 본문이 아니라 헤더(`X-LLM-Key`)로 보내, 본문 로깅에 섞이지 않게 함
- 서버는 제공자를 허용 목록(Gemini·Anthropic·OpenAI)으로만 받고, 전송 주소는 코드에 고정 — 요청이 주소를 바꿀 수 없음(SSRF·키 탈취 방지)
- 키·모델 이름은 형식 검사(줄바꿈·공백 등 차단), 서버는 키를 저장·로그하지 않고, 오류는 HTTP 상태 코드만 돌려줌 (테스트로 키 비노출 확인)
- 배포 응답 헤더: CSP `connect-src 'self'`(페이지가 이 사이트 API 외에는 통신 불가), `frame-ancestors 'none'`, nosniff, no-referrer. API 응답은 `Cache-Control: no-store`
