# 구현 범위

대회 규칙: 직접 구현한 부분과 외부 기술을 구분하고, AI 미적용·미검증 상태와 테스트 계정·샘플·모킹 범위를 밝힌다.

## 직접 구현
- 카드 응답 검증·정규화 (`packages/core/src/cards.ts`): 모델 출력의 키·값을 고정된 어휘로 검사, id 재부여, 추천 1개 보장
- 프로필 계산과 규칙 추천 (`profile.ts`, `recommend.ts`, `presets/`): 규칙 기반, 결정적
- 유지보수 규칙 8종·보안 규칙 9종 프리셋 문구
- 사양서 생성 (`spec.ts`), 작업 계획 기본값 (`tasks.ts`)
- OpenAI 호환 LLM 클라이언트와 모델 폴백 (`llm.ts`)
- 웹 화면 4단계, 요청 핸들러(입력 검증·요청 횟수 제한), 배포 빌드 스크립트

## 외부 기술 (API·라이브러리·모델)
- Google Gemini API (OpenAI 호환 엔드포인트), 모델 `gemini-flash-lite-latest` → `gemini-flash-latest`
- React, Vite, esbuild, TypeScript
- Vercel (배포)

## AI 적용 범위
| 단계 | 방식 |
|---|---|
| 갈림길 카드 생성 | AI (실패 시 기본 카드 5장) |
| 규칙 추천 | **AI 미적용** — 규칙 기반 (설명 가능성을 위해 의도적으로) |
| 작업 계획 | AI (실패 시 프로필 기반 기본 계획) |
| 사양서 조립 | **AI 미적용** — 템플릿 조립 |
| 사후 점검 | 규칙 검사(3개 규칙, 정규식) + AI 판단(나머지 규칙). 규칙 검사로 확정된 위반은 AI 의견으로 뒤집지 않음. AI 실패 시 규칙 검사 결과만 표시 |

## 미검증
- "사양서를 쓰면 토큰·재요청·보안 문제가 줄어든다"는 효과는 아직 실측 전 (비교 실험 예정)
- 사양서 토큰 수는 토크나이저 없이 문자 수로 추정한 값 (화면에 "추정" 표시)

## 샘플 · 모킹 · 테스트 계정
- 기본 카드·기본 계획은 AI 실패 시에만 쓰이며 화면에 "AI 미사용 · 기본값"과 사유를 표시
- 예시 요청 버튼 3개는 입력 편의용 샘플 문장 (결과는 매번 실제 AI 호출)
- 로그인 없음, 테스트 계정 불필요
